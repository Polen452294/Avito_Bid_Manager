# Управление Avito Bid Manager через Telegram

Укажите в локальном `.env` токен **существующего** бота в `TELEGRAM_BOT_TOKEN`
и числовой Telegram ID владельца в `TELEGRAM_ADMIN_IDS=[123456789]`. Оставьте
`MODE=DRY_RUN` для запуска приложения. При первом запуске примените
`alembic upgrade head`, запустите `python -m app.main serve` и отправьте `/start`
в личном чате с ботом. Токен хранится в окружении. Панель доступна указанным
администраторам в личных чатах.

## Главное меню

| Раздел | Действия |
| --- | --- |
| Мои объявления | До пяти объявлений. Добавление по ID, карточка, позиция, статистика, настройки и локальная пауза. Исключение сохраняет историю и освобождает место. Восстановление возвращает карточку в приостановленном состоянии. |
| Управление ставками | Подтверждённая и рассчитанная ставки, ручное предложение, параметры стратегии и список предложений ASSISTED. |
| Бюджеты | Дневные лимиты аккаунта и объявлений, расходы, остаток с резервом, причины блокировки и переключатели уведомлений 80% и 95%. |
| Аналитика | Сегодня, 7 или 14 закрытых дней, одно объявление или сравнение всех. Источники и время данных, отдельный экран рекомендаций PerformanceOptimizer. Пропуски и недостаточное покрытие отображаются явно. |
| История изменений | Расчёты, результаты симуляций, отклонения, ошибки и административный журнал. |
| Расписание | Рабочие часы алгоритма, интервал наблюдения по объявлениям, время отчёта и общая пауза мониторинга. Показывает последний и следующий запуск задач и последнюю сохранённую ошибку. |
| Настройки | Категории уведомлений и срок подтверждения ставки. Критические события доставляются независимо от настройки необязательных категорий. |
| Состояние системы | Состояние БД, планировщика и Avito API, последний цикл, доступность позиций, свежесть расходов и причины блокировки AUTO. «Проверить подключение» выполняет диагностические операции чтения. |
| Остановить автоматизацию | Приостанавливает локальные расчёты ставок и блокирует исполнение ожидающих предложений. Продвижение и списания в Авито продолжаются по настройкам кабинета. |

Из карточки можно изменить целевой диапазон, границы ставки, шаги, cooldown,
лимит изменений за сутки, запросы и регион. Новый запрос вводится в формате
`{"text":"мягкое кресло","region":"Москва"}`. Основной запрос определяет регион
в краткой карточке. Если доступна проверка принадлежности по API, мастер
проверяет ID. При отсутствии проверяемых данных мастер помечает запись
`UNVERIFIED`. Явный отказ в доступе останавливает добавление.

Денежные значения вводятся в целых копейках. Время ежедневного отчёта задаётся
в формате `ЧЧ:ММ` в часовом поясе `TIMEZONE`. Рабочие часы вводятся списком
`[9,10,11]`. Цикл APScheduler проверяет, какие наблюдения пора обновить.
Для каждого источника применяется больший из интервала источника и интервала
объявления. Плановый и ручной циклы используют общую блокировку мониторинга.
Отчёт за вчера отправляется после указанного времени, повторная доставка
одного отчёта контролируется по дате и получателю.

## Режимы и подтверждения

- **DRY_RUN** сохраняет расчёты и историю. Ставки остаются прежними.
- **ASSISTED** формирует предложения для настроенного LOCAL SIMULATOR. Можно
  подтвердить или отклонить их. Автоматическое предложение требует свежих
  наблюдений и подходящего финансового среза.
- **AUTO** заблокирован. Кнопка показывает причины из ReadinessService.
  Для будущего включения нужен отдельный процесс после проверки реального
  чтения, финансовых ограничений, пробной записи и сверки. Разрешение владельца
  должно быть явным и только после успешной проверки readiness.

Для ручной симуляции создайте локальную модель MOCK, установите стартовую ставку
и включите ASSISTED. Откройте «Управление ставками → Выбрать объявление →
Ввести ставку». Бот покажет исходную и новую суммы и срок подтверждения.
Требуется свежий финансовый срез, пригодный для симуляции, например подготовленный
через существующий `import-statistics` с типом `test`. Автоматические расчёты
могут использовать тестовые позиции из `import-positions`.

После подтверждения ExecutionService повторно сверяет режим, конфигурацию,
ставку, паузу и бюджет. Увеличение ставки потребляет право на повышение по
текущему финансовому срезу. Результат обозначается как расчёт, исполнение
в симуляторе, отказ либо результат, требующий сверки. Подпись и UUID кнопки
защищают предложение от изменения и повторного исполнения. Срок предложения
задаётся `TELEGRAM_CONFIRMATION_MINUTES`. Подтверждённые настройки, предложения
и журнал сохраняются в SQLite. Черновик ввода и кнопка сохранения настроек
действуют в текущем процессе. После перезапуска для навигации используется
`/start`.

## Команды

| Команда | Действие |
| --- | --- |
| `/start`, `/help`, `/items` | Меню и список объявлений |
| `/status`, `/cancel` | Состояние системы и отмена текущего ввода настроек |
| `/analytics [today\|7\|14] [ID]`, `/stats`, `/compare [today\|7\|14]` | Аналитика и сравнение |
| `/strategy ID [JSON]`, `/queries ID JSON` | Просмотр стратегии или подготовка правок |
| `/budget [ID] [КОПЕЙКИ]` | Просмотр бюджета или подготовка изменения лимита |
| `/positions ID`, `/position_history ID` | Позиции и наблюдения |
| `/history ID`, `/recommend ID` | История решений и отдельный расчёт DRY_RUN |
| `/pause ID`, `/resume ID` | Предварительный просмотр изменения локальной активности |

## Границы реального управления

Запись ставки в Avito, подтверждение реальной платной записи и AUTO отключены.
Доступность реальных показателей зависит от настроенных контрактов API,
доступа аккаунта и подключённых источников. Тестовые данные и результаты
LOCAL SIMULATOR помечены отдельно. Локальные лимиты ограничивают автоматизацию
программы. Жёсткий лимит реальных списаний и остановка уже активного платного
продвижения управляются в кабинете Авито.
