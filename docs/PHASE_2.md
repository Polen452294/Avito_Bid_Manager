# Фаза 2 — реализация и подключение

Дата: 16.11.2026. Статус: код адаптеров подготовлен, официальная актуальность и
работа с настоящим аккаунтом не подтверждены. Полностью завершённой production
интеграцией эту фазу считать нельзя. К Фазе 3 работа не переходила.

## Реализовано

- Асинхронный httpx-клиент: ограниченные повторы чтения, обновление после 401,
  типизированные ошибки, тайм-ауты, Retry-After, ограничение частоты методов.
- Client Credentials OAuth для собственного аккаунта; токен хранится в памяти.
- Отдельные адаптеры аккаунта, объявлений, CPX, CPA, услуг и статистики.
- Запросы изменения ставки, сохранение намерения в существующей БД, проверка
  фактической ставки и лимита/срока, сверка после неопределённого ответа.
  Эти пути доступны исключительно в изолированных HTTP-тестах, не в сети.
- UNKNOWN/FAIL_SAFE при неудачной сверке, отсутствие слепого повторения записи.
- Диагностика чтения без платных действий и без вывода секретов/персональных полей.

## Граница подтверждения

Официальные страницы в этой среде возвращают 429. Использован дополнительный
снимок OpenAPI от 03.10.2026, а не выдуманные mock-контракты. Ответы тестов
синтетические, составлены по снимку и не получены от настоящего аккаунта.
Для сети требуется предоставить официальные OpenAPI 3.0 JSON-экспорты.
Клиент сравнивает схемы запроса/ответа, параметры и security для каждой операции.
Расхождение блокирует конкретную операцию. Совпадение файла не удостоверяет его
происхождение: владелец должен получить его из официального каталога Авито.
Не используйте приложенный справочный снимок вместо официального экспорта.

## Подключение аккаунта

1. В официальном кабинете Авито получите Client ID и Client Secret для собственного
   аккаунта и выясните доступность API для вашей категории/тарифа. Не отправляйте
   секреты в чат. Точный интерфейс кабинета из этой среды не проверен.
2. Получите из официального каталога JSON OpenAPI разделов auth, user, item,
   cpxpromo, auction, promotion. Сохраните, например, в `data/official/`.
   Если экспорт недоступен, запросите его у поддержки; обход защиты не нужен.
3. Скопируйте `.env.example` в `.env`, если файла ещё нет. Заполните локально:

```dotenv
MODE=DRY_RUN
AVITO_CLIENT_ID=ваш_client_id
AVITO_CLIENT_SECRET=ваш_client_secret
AVITO_ITEM_IDS=[123456789]
AVITO_EXPECTED_ACCOUNT_ID=123456
AVITO_OFFICIAL_SPEC_PATHS=["data/official/auth.json","data/official/user.json","data/official/item.json","data/official/cpxpromo.json","data/official/auction.json","data/official/promotion.json"]
```

Укажите настоящие ID. EXPECTED_ACCOUNT_ID можно временно опустить для первого
чтения аккаунта, затем зафиксировать полученный ID. `.env` и `data/` исключены из Git.

4. Из корня проекта в PowerShell выполните:

```powershell
$env:PYTHONUTF8='1'
.\.venv\Scripts\python -m app.cli check-avito
```

Без credentials: NOT_CONFIGURED, код завершения 0. Без подходящего auth-контракта:
CONTRACT_BLOCKED, код 0, сетевых вызовов нет. Ошибки конфигурации — код 2;
частичная доступность/отказы — код 1. Успешная диагностика — READ_CHECKS_PASSED,
но write_permissions всегда NOT_TESTED. Доступность моделей проверяется по каждому
объявлению. 403 не позволяет автоматически определить, виноваты тариф, права или категория.
Диагностика может занять время из-за ограничений частоты. Не запускайте несколько
диагностик одновременно: локальный ограничитель частоты действует в одном клиенте.

5. При CONTRACT_BLOCKED после загрузки схем нужно разобрать различия контрактов,
   а не отключать проверку. При ACCESS_DENIED уточнить права у Авито. При 429
   дождаться разрешённого срока и повторить диагностику позже.

Сервис `serve` не подключён к автоматическому live-биддингу. Реальные записи и
AUTO не включаются этой инструкцией. Для них потребуются отдельная проверка
актуальных контрактов, прав, финансовой свежести и разрешение владельца.
