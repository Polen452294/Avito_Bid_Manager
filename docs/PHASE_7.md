# Фаза 7. Подготовка локального контура

Compose запускает один процесс в DRY_RUN. Сервис удерживает блокировку SQLite на протяжении миграции, восстановления и работы планировщика. Перед изменением схемы существующей базы создаётся отдельная проверенная копия. Telegram ASSISTED по-прежнему применяет ставки в локальном симуляторе.

| Проверка | Команда |
|---|---|
| Демонстрация решения на изолированной БД | `python -m app.main demo` |
| Состояние существующей БД, планировщика и уровней готовности | `python -m app.cli readiness` |
| Диагностика Авито через разрешённые операции чтения | `python -m app.cli check-avito` |
| Готовность с актуальными результатами диагностики Авито | `python -m app.cli readiness --check-avito` |
| Healthcheck процесса | `python -m app.main health` |

Диагностика Авито печатает JSON в stdout. POST используется для OAuth и предусмотренных контрактом запросов чтения. Результаты по CPX и CPA отображаются отдельно. `bid_write=UNVERIFIED` и `live_positions=UNAVAILABLE` блокируют реальное исполнение. `checked_at` фиксирует текущее испытание. Последняя успешная живая проверка сохраняется в существующей мигрированной БД для той же конфигурации. История проверок не участвует в вычислении текущей готовности.

ASSISTED_READY фиксирует запрет на реальный адаптер в данном релизе. AUTO_READY дополнительно требует оперативных наблюдений, финансовой свежести и испытаний. Готовность и разрешение на исполнение остаются отдельными проверками.

## Контракт будущего реального адаптера

Адаптер должен принимать идентификатор операции, аккаунт, объявление, модель и ожидаемую ставку. До записи оркестратор под блокировкой аккаунта проверяет режим и отдельное разрешение владельца, принадлежность объявления, подтверждённый контракт и доступные значения, лимиты, свежесть финансов и наблюдений, cooldown и отсутствие незавершённых операций. Сохраняет намерение и резервирует финансовый срез в одной транзакции, затем освобождает транзакцию до HTTP. Запрос отправляется один раз. Результат проверяется чтением с сопоставлением объявления, ставки, модели и параметров продвижения.

При тайм-ауте, сбое записи результата или падении процесса восстановление выполняет чтение. Если результат нельзя установить, целевой статус реального адаптера — `REQUIRES_RECONCILIATION`, с блокировкой новых операций и записью причины. Локальный журнал использует `UNKNOWN` с FAIL_SAFE. Он проверен на симуляторе и mock-транспорте. Подтверждение результата только совпадением суммы недостаточно для включения реального адаптера.
