## Проверенные границы подсистем

- Avito transport и auth. Асинхронный клиент закрывается владельцем в `finally`. TokenCache обновляет credentials под lock. Чтение имеет ограниченные повторы и выдержку по ответам 429. Лимиты в памяти отдельного клиента и справочные значения из снимка требуют проверки на реальном доступе.
- SQLite и доменная модель. Идентификаторы операций уникальны, деньги хранятся целыми копейками, JSON ответа для финансов декодируется через Decimal. Репозиторий применяет лимит пяти объявлений под write lock. Для реальной нагрузки SQLite нужен локальный том с корректной блокировкой файлов.
- PositionProvider и анализатор. Ручной импорт пригоден для локальных наблюдений, mock — для воспроизведения, Provider official/browser возвращает UNSUPPORTED. External имеет точку подключения разрешённого адаптера. Средняя позиция служит аналитике, ограниченная глубина поиска относится только к проверенному диапазону.
- BudgetController, оптимизатор, распределение и ретроспектива. Просроченный, неполный или неизвестный срез блокирует повышение. Claim привязан к общему срезу аккаунта. Коррекция того же среза не возвращает возможность повторного повышения. Исторические рекомендации остаются локальными. При действующем продвижении расходы в Авито могут продолжаться независимо от локального guard.
- Telegram, задания и администрация. Проверяется allowlist администратора и личный чат. Callback подписывается, изменения сравниваются с исходной конфигурацией, подтверждения предложения ограничены по времени. CLI-импорт позиций теперь выполняется при остановленном сервисе, чтобы не конкурировать с фоновым циклом. Тесты Telegram используют имитацию API.
- Планировщик и восстановление. Одновременно работает один экземпляр на одном томе. Задания ограничены max_instances, монитор и аналитика имеют собственные блокировки. Для Linux предусмотрена обработка SIGTERM, тест Windows подтверждает остановку процесса и отказ healthcheck после неё.
